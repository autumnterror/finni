# Интеграция и параллельная разработка
Первичная реализация: `feature/pet-flight-mini-game`, коммиты `1815a03` и `26c1a2e`, от базы `5e77e16`. Интеграция: `feature/flappy-bird-mini-game`, исходный HEAD `1534133` с уже внедрённой рыбалкой.

## Проверенные контракты
RoomGameLauncher.openGame(String) диспетчеризует `flight` через FlightFeature.getApi().open(), а `fishing` — через FishingFeature.getApi().open().
Nav3 graph содержит entries обеих игр. Полёт подключается через FlightApi.installEntries. Повтор — состояние одной ViewModel, не новый маршрут.
Имя и кастомизация принадлежат feature/pet. FlightHost передаёт стабильный ID текущей внешности для сохранения игровой сессии, а сама сцена получает составной bitmap актуального питомца через PetApi.
mini-games/common занимается вопросами; создавать вторую модель вопроса или делать аркаду викториной не нужно.

## Владение
FlightHost: environment(), applyPlayEffect(facts), feedbackSettings()/saveFeedbackSettings().
FlightDependencies: host, flightDao, transactionRunner, navigator, config JSON, clock.
Flight module не импортирует Room/GameState/GameSession. Их связывает app mediator.
Room владеет новой зоной `flight`, её расположением и PNG на прозрачном фоне. Общая `MiniGameAccess` задаёт временную открытость полёта; её читают каталог комнаты, FlightHost и обработчик совместной игры. Модуль полёта не списывает деньги. Прямой запрос покупки уже открытой игры возвращает AlreadyOwned без фиктивной транзакции.

## Данные
FlightDatabase создаётся в app. Схема версии 1 содержит `flight_progress(profileId, payload)`.
Одна агрегатная JSON-запись содержит активный мир с ограниченным числом препятствий, рекорд каждой версии, значки, последний результат и очередь недоставленных эффектов. История каждого кадра и нажатия не накапливается.
Repository упорядочивает записи через Mutex и RoomTransactionRunner. Checkpoint сохраняется только для текущей незакрытой сессии; финализация не может быть затёрта поздним кадром. При одинаковом tick отбрасывается снимок с меньшим числом взмахов.
Общий эффект питомца использует таблицу `pet_play_effects`: подтверждение операции и изменение счастья происходят в одной транзакции. Запрос можно повторить после сбоя доставки; деньги не затрагиваются. Подтверждения сохраняются для защиты от повторного начисления.

## Совместимость с соседней рыбалкой
Используются единственные PetPlayCompletion, PetPlayReward, completePetPlay и DAO эффектов. Поля validActionCount и activePlayMillis расширяют контракт совместимыми значениями по умолчанию; вызов рыбалки через validCastCount продолжает работать. Минимальные 10 секунд применяются только к полёту.
Сохранена существующая MiniGameAccess из рыбалки, расширенная открытыми играми `ball`, `fishing`, `flight`. Отдельной конкурирующей политики доступа нет. Проверки входа и применения эффекта используют один контракт.
При проверке обновления ранее выданного preview обнаружены два варианта FinPetDatabase версии 8: основной с `fishing_progress` и ранний полёт без неё. Поэтому объединённая база имеет версию 9. Прежние миграции 6→7 и 7→8 сохранены; новая 8→9 создаёт `fishing_progress` только при отсутствии. Существующие записи профиля, покупок, транзакций, эффектов и рыбалки сохраняются. Это проверяется для обеих схем 8, а также для версий 6 и 7.
Полёт продолжает храниться в отдельной FlightDatabase версии 1. Формат JSON рыбалки и отдельная база полёта не меняются; сброс данных не используется.
Настройки используют общий SharedPreferences `finpet_feedback` и ключи `sound`, `haptics`, `reduced_motion`. Адаптер переводит настройки в модель полёта без зависимости от FishingFeedbackSettings.

## Восстановление
Новый вход: проверить среду → прочитать прогресс → завершить сохранённую попытку с исходом → доставить ожидающие эффекты → восстановить активный мир либо создать новый → показать сцену и 3–2–1 → автоматический взлёт. Домашнего экрана и меню паузы нет.
Snapshot сохраняет версию, seed, состояние PRNG, tick, препятствия, игровые координаты, счёт, число взмахов и исход. Удержание не сохраняется.
Чужой профиль не может применить эффект к текущему. Несовместимый rules snapshot убирается; рекорды сохраняются по версии. Правила 2 не требуют миграции базы или схемы JSON.
Неизвестная схема JSON или повреждение вызывают ошибку без автоматического сброса. При ошибке записи выход возвращает в комнату без повторной обязательной записи; дальнейшее восстановление использует последний подтверждённый снимок.

## Риск интеграции
По актуальному решению пользователя полёт открыт сразу и в обычной, и в preview-сборке. Чтобы позже вернуть покупку, убрать `flight` из списка открытых игр в MiniGameAccess: каталог уже хранит резервную цену 300 и уровень 1. Существующие покупки останутся действительными. Изменение открытости не требует миграции и не перезаписывает сохранения.
Модули полёта и рыбалки не зависят друг от друга; их связывает app.
