# Feature: Shop

## Goal

Предоставить один переиспользуемый экран каталога для продуктового и будущих магазинов.
Экран получает описание витрины, произвольные категории и товары, показывает актуальный баланс
и фильтрует сетку без знания конкретного типа товара.

Старый `:feature:product-market` остаётся изолированным legacy-кодом. Новый `:feature:shop`
не использует его модели, данные, базу или UI и является основой дальнейшей разработки.

Текущий этап включает только экран продуктового каталога. Корзина, подтверждение и покупка
будут отдельным следующим этапом со своим согласованным дизайном.

## Educational Goal

Ребёнок видит цену товара и его игровой эффект до будущей покупки. Просмотр каталога и
переключение категории сами по себе не являются образовательным evidence.

## Ownership

This feature owns:

- универсальный экран каталога;
- выбранную категорию и фильтрацию списка;
- состояния загрузки, пустого результата и ошибки загрузки;
- навигационный API открытия витрины.

This feature does not own:

- корзину, оформление или подтверждение покупки;
- баланс, списание денег и журнал транзакций;
- инвентарь или применение эффектов к питомцу;
- определения конкретных каталогов и балансировку цен;
- данные старого `:feature:product-market`.

This feature consumes:

- `SellableCatalog`, `StorefrontDefinition`, `SellableItem` и категории из `:core:products`;
- `ShopHost` для подготовки игрока и наблюдения за балансом;
- `ShopCatalogRegistry`, `ShopArtworkResolver` и `ShopItemDetailsResolver`;
- общие компоненты и токены `:core:designsystem`.

This feature provides/emits:

- `ShopApi.open(storeId)`;
- Nav3 entry экрана каталога;
- события загрузки, повтора, выбора категории и возврата назад.

## Modules

- `:core:products` — общие модели товара и конфигурация `GroceryCatalog`;
- `:core:designsystem` — кнопка назад, chips, кнопки и lazy-коллекции;
- `:feature:shop` — generic UI, UI-state, ViewModel и навигация;
- `:app` — подключение продуктового каталога, баланса и навигации.

Отдельный feature-модуль для каждого типа магазина не нужен. Новый тип магазина обычно
добавляет каталог, категории и resolvers; отдельная feature оправдана только для собственного
пользовательского сценария, а не для ещё одной сетки.

## User Flow

1. Игрок открывает продуктовый магазин из комнаты.
2. Экран показывает заголовок, баланс, data-driven chips и сетку товаров.
3. Нажатие на chip сразу фильтрует список.
4. Кнопка назад возвращает игрока в комнату.

## Domain Model

Общий минимальный контракт товара:

```text
SellableItem
- id: ProductId
- title: String
- imageKey: ProductImageKey
- priceRub: Long
- categoryId: StoreCategoryId
- description: String? (optional)
```

`FoodItem` расширяет его эффектами `satietyPercent` и `happinessPoints`. Механики жажды нет,
поэтому `thirstPercent` отсутствует. Вода исключена из продуктового каталога.

`StorefrontDefinition` содержит `StoreId`, заголовок, подпись общего фильтра, произвольные
категории, список товаров и `StoreGridLayout`. Категории и число колонок не зашиты в UI.

`GroceryCatalog` содержит 39 позиций из референса:

- 20 продуктов;
- 10 блюд;
- 9 напитков.

## UI States

- `loading` — подготовка игрока и загрузка витрины;
- `content` — категории и сетка каталога;
- `empty` — выбранная категория не содержит товаров;
- `error` — каталог не удалось загрузить, доступен повтор.

Карточки имеют одинаковую фиксированную высоту и отдельные слоты изображения, названия,
эффекта и цены. Длинные названия не меняют размер карточки. Шапка использует компактный
заголовок и адаптирует размер суммы для пяти и более цифр. Кнопка назад имеет touch target
56 dp. Сытость обозначается простой контурной иконкой яблока.

Индивидуальные изображения товаров в репозитории пока отсутствуют. `ShopArtworkResolver`
готов к их подключению; до передачи архива или точного пути показывается нейтральный
placeholder. Общий референс не нарезается на игровые ассеты.

## Persistence

Экран каталога ничего не сохраняет. Выбранная категория живёт только в UI-state. Таблицы
корзины, чеков и инвентаря на этом этапе не создаются.

## Events

- `Load`;
- `Retry`;
- `CategorySelected(categoryId?)`;
- `Back`.

Денежных или игровых side effects в текущем экране нет.

## Skill Integration

SkillId: отсутствует для просмотра каталога.

Framework level: не применяется.

Evidence types: не создаются.

Feedback: карточка заранее показывает цену и эффект; оценка решения появится вместе с
полноценным purchase flow.

## Configuration

- набор витрин в `ShopCatalogRegistry`;
- заголовок и подпись общего фильтра;
- категории и их порядок;
- список и порядок товаров;
- число колонок сетки;
- цены и пищевые эффекты;
- изображения и детали через resolvers.

Балансировочные числа хранятся в каталоге, а не в Composable.

## Edge Cases

- неизвестный `StoreId`;
- пустая категория;
- несуществующая категория в событии фильтра;
- баланс больше 10 000;
- длинное название товара;
- отсутствующее изображение;
- повторная загрузка после ошибки.

## Acceptance Criteria

- Телефон в комнате открывает новый `:feature:shop`, а не legacy product-market.
- Активная навигация и DI не зависят от `:feature:product-market`.
- Экран принимает любой `SellableCatalog`, категории и конфигурацию сетки.
- Chips `Все`, `Продукты`, `Блюда`, `Напитки` фильтруют каталог без hardcode в UI.
- Каталог содержит 39 стабильных ID: 20 + 10 + 9; воды и эффекта жажды нет.
- Все карточки имеют одинаковый размер.
- В шапке помещается пятизначный баланс; заголовок не вытесняет баланс.
- Используется общая 56 dp кнопка назад из design system.
- Сытость показана простой иконкой яблока.
- На экране нет кнопки, состояния, диалога или persistence корзины.
- Compose previews находятся рядом с соответствующими компонентами.
- Android UI test проверяет вход из комнаты, фильтрацию и возврат назад.
