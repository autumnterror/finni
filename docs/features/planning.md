# Feature: недельный план

## Цель

В начале второй и каждой следующей игровой недели ребёнок распределяет доступные деньги между обязательным, желаниями и накоплениями. На первой неделе план не требуется. После сохранения план доступен через календарь на стене комнаты.

## Образовательная цель

План создаёт контекст для будущего сравнения намерения и действий. Модуль не начисляет XP и не меняет `SkillId`: эти правила появятся у недельного итога и образовательных сценариев.

## Владение

Модуль `feature:planning` владеет:

- процентным планом недели;
- расчётом плановых сумм;
- фактическими суммами по трём категориям;
- отображаемым статусом выполнения плана.

Модуль не владеет кошельком, выдачей денег, покупками, накопительной целью и XP. Он получает доступный остаток только при сохранении плана. `feature:week` определяет номер текущей недели, а `feature:room` показывает диалоги и принимает нажатие календаря.

## Модули и контракты

`PlanningApi` предоставляет:

```kotlin
suspend fun savePlan(weekNumber, availableRub, percentages): SavePlanResult
fun observePlanProgress(weekNumber): Flow<WeeklyPlanProgress?>
suspend fun recordActual(operationId, weekNumber, category, amountRub): RecordActualResult
```

Следующие модули должны вызывать `recordActual` только после успешной идемпотентной денежной операции:

| Событие | Категория |
| --- | --- |
| обязательная покупка | `MANDATORY` |
| необязательная покупка | `WANTS` |
| перевод в копилку | `SAVINGS` |

`operationId` обязателен и защищает от повторного учёта при двойном тапе, восстановлении экрана или повторном callback. Повтор с тем же payload возвращает `AlreadyRecorded`; тот же ID с другими данными возвращает `OperationIdConflict`.

## Пользовательский поток

1. Игрок завершает седьмой день первой недели и попадает в начало второй.
2. На экране комнаты открывается обязательное окно плана.
3. Три ползунка всегда сохраняют суммарно ровно 100%; перемещаемый ползунок меняет две остальные доли пропорционально.
4. До кнопки «Сохранить» изменения существуют только в локальном черновике.
5. После сохранения план становится неизменяемым для этой недели.
6. Нажатие на календарь открывает суммы плана, фактический результат и прогресс-бары.

## Доменная модель и визуальный статус

`PlanPercentages` содержит три неотрицательных целых процента с суммой ровно 100. Плановая сумма обязательного и желаний вычисляется от доступного остатка; остаток после округления относится к накоплениям, поэтому все три суммы в точности дают доступный остаток.

В календаре серый трек показывает план, а цветная часть — фактическую сумму:

- зелёная — в рамках плана;
- жёлтая — превышение до 25 %;
- красная — превышение свыше 25 % или расход при нулевом плане.

`PlanningConfig.seedDemoProgress` может добавить после сохранения демонстрационные операции: зелёную, жёлтую и красную. В обычной игре он выключен: реальные магазин, копилка и платные зоны передают факты сами. Режим предназначен только для отдельного demo-профиля.

## Persistence

В общей Room-базе добавлены `weekly_plans` и `plan_actual_operations`; миграция `11 → 12` не удаляет существующее сохранение. План сохраняется один раз на номер недели. Фактические операции имеют первичный ключ `operationId`.

## Edge cases

- На первой неделе сохранение плана отклоняется.
- План нельзя изменить после сохранения.
- План не резервирует деньги и не блокирует доступную неудачную покупку.
- Неположительная сумма и пустой ID операции отклоняются.
- Нельзя записать факт до сохранения плана.
- Деньги начисляет только недельный rollover; открытие или закрытие диалога плана их не меняет.

## Критерии приёмки

- На нулевом дне и в первой игровой неделе окно плана не показывается.
- Со второй недели окно появляется до продолжения игры, пока план не сохранён.
- В любой момент редактирования сумма ползунков равна 100 %.
- Календарь показывает все три категории и корректный статус выполнения.
- Повторный учёт одной операции не меняет прогресс второй раз.
- План и фактические суммы сохраняются после перезапуска приложения.
