# Состояние игры

## Назначение

Модуль хранит нефинансовый прогресс игрока: уровень, показатели питомца и
купленные игровые зоны. Баланс, регулярные поступления и финансовую историю
хранит модуль `Economy`; экранные фичи объединяют оба потока через их API.

## Публичные операции

- `GameStateApi.initialize()` возвращает сохранённую игру или создаёт новую
  с настройками `GameStateInitialConfig`.
- `observeState()` предоставляет Flow актуального прогресса.
- `buyZone(ZoneOffer)` проверяет владение, уровень и достаточность средств,
  затем покупает зону. Результат описывается `ZoneBuyResult`.

Покупка выполняется одной транзакцией общей БД: цена списывается через
`EconomyApi`, а владение зоной сохраняется в `GameState`. Повторная покупка уже
принадлежащей игроку зоны возвращает `AlreadyOwned` и не списывает деньги.

## Хранение и интеграция

`GameStateRepository` работает через `GameStateLocalDataSource` и DAO:

| Таблица | Содержимое |
|---|---|
| `game_sessions` | Нефинансовый прогресс и показатели питомца |
| `room_zones` | ID купленных зон и время покупки |
| `financial_operations` | Единая история операций, принадлежащая `Economy` |

База `FinPetDatabase` создаётся в `app`. `GameStateMediator` передаёт DAO и
`RoomTransactionRunner` и `EconomyApi` через зависимости фичи. Условия и
расположение зон задаёт модуль `room`; модуль состояния отвечает за сохранение
владения и координирует атомарную покупку через общий финансовый контракт.

Версией общей схемы и миграциями владеет модуль `app`; обновления сохраняют
игровой прогресс и переносят прежние финансовые записи в `Economy`.
